# Security Policy

Thank you for helping keep this repository and its users safe. This
repository is intentionally minimal — it is documentation only, with no
dependency manifest, no build step, and no executable code — but security
reports are still taken seriously. Please read this policy before reporting
a vulnerability.

## 1. Supported versions and scope

This repository has **no formal release or versioning system** — there are
no tagged releases, published packages, or maintained branches other than
`main`. Security reports should therefore target:

- the **latest state of the `main` branch** of
  [`quanticsoul4772/hygiene-streak-target`](https://github.com/quanticsoul4772/hygiene-streak-target).

Examples of issues that are in scope:

- Malicious, misleading, or unsafe content in the repository's files (for
  example, links that point somewhere harmful).
- Repository configuration problems that could put contributors or users at
  risk.

Issues in your own fork, or in third-party sites linked from this
repository, are out of scope — please report those to the relevant
maintainers instead.

## 2. How to report a vulnerability

**Please do not report security vulnerabilities through public GitHub
issues, discussions, or pull requests.** Public reports can expose others
to risk before a fix is available.

Instead, use GitHub's **private vulnerability reporting**:

1. Open the repository's
   [Security advisories page](https://github.com/quanticsoul4772/hygiene-streak-target/security/advisories).
2. Click **Report a vulnerability** and fill in the form.

This sends the report privately to the maintainer, and GitHub provides a
private channel for any follow-up discussion.

If you are unable to use private vulnerability reporting, you may instead
open a plain issue that says only that you have a security concern and asks
the maintainer to get in touch — **do not include vulnerability details in
the public issue itself**.

## 3. What to include in a report

There is no report template, so plain free-form reports are welcome. To
help the maintainer understand and act on your report quickly, please
include:

- a clear, descriptive title;
- a description of the issue and why you believe it is a security problem;
- the affected file(s) or repository setting(s), with links to the relevant
  lines where possible;
- steps to reproduce or verify the issue; and
- any suggested fix, if you have one.

## 4. What to expect after reporting

This repository is maintained by a single maintainer on a best-effort
basis, so response times are pragmatic rather than guaranteed:

- **Acknowledgment** — you should receive an acknowledgment of your report
  within **7 days**.
- **Assessment and fix** — the maintainer will assess the report and aim to
  resolve confirmed issues within **30 days**, keeping you informed of
  progress through the private report thread.

If you have not heard back within 7 days, please follow up on the private
report thread — a reminder is welcome, not a nuisance.

## 5. Public disclosure

Please practice **coordinated disclosure**: keep the details of your report
private until the maintainer has confirmed and resolved the issue, or until
you have agreed on a disclosure timeline together. Once a fix is in place,
you are welcome to discuss the issue publicly, and credit will gladly be
given to reporters who wish to be named.

Thanks again for reporting responsibly!
